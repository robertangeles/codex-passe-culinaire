# Phase 4 discovery contract

Parent-owned architecture within the approved plan. Public data reads use overrideAccess:false and published base records. noIndex excludes documents from sitemap, feeds, Markdown mirrors and both LLM outputs; excludeFromSitemap only affects sitemap. Private user fields never enter graph builders. Unknown facts and placeholder media are omitted from structured data.

Schema builders are pure typed functions under src/lib/seo. core.ts supplies SchemaNode/JsonValue, confirmedText, absolutePublicUrl(value, origin), isoDate, publicMediaUrl(value, origin), entityIds(origin), siteOrigin and serializeJsonLd(nodes). Each builder receives origin explicitly. IDs use /#organisation, /#website, /culinaire-kitchen#brand, /culinaire-kitchen#software and /journal/author/<slug>#person. Route entities use their canonical route plus #article, #service, #event, #course, #breadcrumb or #faq. Serialisation escapes script termination characters and Unicode separators. Optional fields remain absent when unconfirmed. An editor override is validated before merging and cannot replace identity or entity relationships.

All page metadata must include a canonical. Graphs may be split into a shared organisation/website script and page-specific scripts with matching IDs. Request-dependent contact/search and authenticated preview remain private. Preview graphs must not imply publication and preview metadata stays noindex/nofollow.

Retain the requested root sitemap names: /sitemap.xml is the index; children are /sitemap-pages.xml, /sitemap-posts.xml, /sitemap-taxonomies.xml, /sitemap-authors.xml, /sitemap-services.xml and /sitemap-training.xml. Other outputs are /feed.xml, /feed.json, /robots.txt, /llms.txt, /llms-full.txt and /journal/<slug>.md. Use an explicit framework rewrite for the Markdown suffix so it cannot collide with the journal HTML page. Full exports use paged public reads without an arbitrary content cap. Finish required database work before committing a successful response; database failure must not produce a success-shaped empty export.

The curated llms index uses site-settings.curatedLinks, validated against real eligible public destinations. Ten distinct eligible destinations remain a production content gate. Do not publish draft sample offerings or invent a tenth destination to satisfy it. Contact is a real public destination but its per-visitor form response stays private. User-provided external credentials, social profiles, images and booking facts remain production inputs.

Export response generation uses cursor batches of at most 100 hydrated records and a temporary UTF-8 file. The generator must finish successfully before a 200 response is constructed, then the completed file streams to the client and is removed on stream close. Route handlers read committed public content on demand; explicit crawler cache headers retain the required 600-second shared cache contract. The supported Caddy configuration does not install an additional response cache. Any future CDN must support publication-triggered purging before it can meet the 60-second visibility requirement.

Schema property checks use the primary definitions at https://schema.org/Brand and https://schema.org/Person. Brand does not carry parentOrganization; the organisation's brand property supplies that relationship. CMS record timestamps do not become Person dateCreated/dateModified. An office address does not establish a service's geographical coverage, so areaServed awaits a confirmed service range. Testimonial graphs and visible detail-page quotes use the same published, related records.

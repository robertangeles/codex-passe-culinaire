# Front-end integration contract

This is a parent-owned implementation handoff for Phase 3, within the approved plan. Generated Payload types and the accepted Phase 2 schemas are authoritative. Do not implement against guessed field names.

- Preserve the company-to-product home journey and verified copy in docs/designs/product-facts.md.
- Public content queries explicitly respect Payload access, published state and safe author fields. Staff/preview queries use a separate uncached path.
- Use the existing ISR approach with a shared public-content cache tag and 600-second revalidation. Prefer broad invalidation for this small site over a new dependency graph; committed jobs expire that tag immediately and invalidate affected route outputs. Public links may use ordinary anchors, avoiding stale prefetched content and unnecessary prefetch traffic.
- Resolve draft mode outside public cache functions. Installed Next 16.3.6 draft-mode.js returns a disabled provider during prerender; only enabled preview requests need authentication/header reads. A forged or stale preview cookie must not grant access. Verify the resulting public/preview cache headers in production.
- Each route should share one request-scoped view-model promise between metadata and page rendering, completing its required reads before emitting a successful response. Avoid loading.tsx/Suspense boundaries that conceal a required-query failure behind an already-streamed HTTP 200.
- Each route owns one main landmark with id="main-content" and tabIndex={-1}, so the skip link moves keyboard focus into the content.
- Render all CMS and Lexical content on the server. Each document has exactly one h1; the first Hero may own it, otherwise the route title does. Later hero/section headings use h2.
- Render all 15 blocks. Dynamic feeds resolve only published records, in bounded queries; batch/reuse requests within a render rather than fetching the same collection per block.
- Use the uploaded AVIF/WebP variants through responsive picture sources, with actual dimensions and alt text. Reserve hero layout space, load the hero eagerly and below-fold media lazily. Keep captions and credits visible where supplied.
- Gallery permits 2–12 images and retains readable DOM order. No carousel, masonry JavaScript package or shadow cards.
- Choose seasonal hero images using the current month in Australia/Melbourne: summer Dec–Feb, autumn Mar–May, winter Jun–Aug, spring Sep–Nov; fall back to the ordinary hero image.
- Render controlled embeds only behind an explicit external-content flag defaulting off; the fallback is a descriptive external link. Never execute arbitrary stored HTML.
- Validate links before emitting href/src. Accept safe relative paths and configured external HTTPS destinations; reject protocol-relative, javascript/data and malformed URLs. Optional missing links are omitted.
- Use exact tokens/local fonts, an asymmetric 12-column layout, 62ch prose, semantic landmarks and visible focus. No image-led claim is implied by the labelled placeholders.
- Header uses the seeded navigation. Nested items remain keyboard-usable. Footer includes editable columns/legal copy and the explicit ABN placeholder.
- Manual theme control is a small client interaction, retains system preference until overridden, persists to localStorage and tolerates storage failures. Prevent an avoidable theme flash; reduced motion disables reveals.
- Services/training/journal show calm truthful empty states while seed records remain drafts. Training keeps published past/cancelled detail pages and distinguishes eventStatus from publication state.
- Journal details, categories, tags and authors use pagination, canonical routes and 404 handling. Author output never includes email, roles or authentication fields.
- Search uses PostgreSQL full-text search over derived visible page/post text, parameterised input and the published filter. Empty/invalid/large queries need explicit bounds and readable results.
- Contact includes the approved reply email. Form submission uses the accepted persistence helper, receipt idempotency and actual delivery state. Preserve user input on validation failure, make field errors accessible, and retain DB-saved enquiries when notification fails.
- Any per-visitor contact receipt or preview state makes that response private/no-store; never put a shared generated request ID in a publicly cached form.
- Publish/unpublish/rename/delete invalidation runs from committed jobs, covers dependent views and never restores an old job snapshot. Author, taxonomy, testimonial, media and global edits invalidate the affected public views as well. Revalidation and preview endpoints authenticate independently.
- Required database lookup failure must satisfy the approved 503/no-store contract at a verified response boundary. The isolated Next 16.3.6 production probe returned 500 and omitted error.tsx copy from initial HTML. Verify the approved Caddy interception response with readable server-rendered copy, and prove required reads finish before a successful stream begins. A React error screen is insufficient.
- Existing Next/Payload stack and 120 kB home-JS limit remain in force while D6 is pending. Do not treat the unsubmitted default selection as approval.

Listing routes use path pagination: `/journal/page/2`, `/journal/category/<slug>/page/2`, `/journal/tag/<slug>/page/2`, and `/journal/author/<slug>/page/2`. Page 1 links use the unpaginated canonical base. Pages are bounded to 1–1000 with 12 journal items per page, explicitly showing the bound for larger lists, stable publication-date/ID ordering, and 404 for out-of-range later pages. This avoids request-query-dependent rendering for public ISR pages. Search remains query-based and contact remains private. CMS slug validation now matches the 200-character bound used by routes, preview and invalidation, preventing an editor from saving an address that cannot be served or refreshed.

Contact uses a private dynamic `/contact` page with a server-generated UUID per response and a progressively enhanced server-action form (`useActionState` permalink `/contact`). The shared persistence helper owns validation, duplicate protection and notification state. Field errors retain visitor input. Saved/emailed/notification-failed states are distinct; do not invite a duplicate resend after a durable save. No personal input enters a URL or shared cache. The action accepts only named public fields and obtains the rate-limit source from a validated `X-Passe-Client-IP` only when `TRUST_PROXY=true`; otherwise it uses a shared untrusted-source bucket. Production Caddy must overwrite that header with the direct peer and Next must bind to loopback. Never trust arbitrary `X-Forwarded-For`.

Verification: fetch complete content with JavaScript disabled; exercise drafts/404/DB failure, mobile/keyboard/theme/contact/search, anonymous API privacy, authenticated preview cache isolation, both publication revision orders and public freshness within 60 seconds. Run the required four checks after each executor handoff; parent reads the full diff and obtains an independent reviewer verdict.

Author queries filter by slug with overrideAccess:false. Users.read enforces publicProfile visibility; callers must not query that private field directly because Payload rejects anonymous field queries. Search uses parameterised published-base-record SQL and partial GIN indexes; results are bounded to 100 pages and disclose this limit when reached.

Managed redirects run in the supported Next 16 Node proxy before public GET/HEAD rendering. Exact indexed lookups use a server-only Symbol capability with overrideAccess:false; anonymous HTTP collection reads remain denied. All destinations stay local, infrastructure paths are protected after repeated decoding, chains are bounded and cycles fall through. Redirect responses use no-store so administrator corrections take effect immediately. This adds one indexed lookup to ordinary public requests; performance acceptance must include that cost.

The production response boundary is `deploy/Caddyfile`, not a bare public Next listener. Next 16.3.6 returned readable 404 content only after hydration even with root and nested not-found experiments. Caddy serves `public/errors/404.html` for public 404 responses and `503.html` for public upstream failures, including connection failures. These documents contain complete text and licensed local fonts without JavaScript. Admin/API/media/framework responses retain their own behaviour. Caddy adds the explicit public cache directive only to Next's shared s-maxage responses and does not change private responses. Fonts and error CSS remain available when Next is down. Configure SITE_ADDRESS, APP_ROOT and PORT in Caddy's separate service environment; bind Next to loopback, then enable TRUST_PROXY. Phase 7 must retain this boundary in the full service/deployment instructions.
